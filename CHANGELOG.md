# Changelog

## v23.09 / 363 - 2026-08-03

- KIA app `23.09 / 363`: `updates/kia_363.apk`. Для исправления свежести фоновых данных одновременно выпущен universal Yandex Navigator Kia mod `7.10-kia.20260723-freshness / 71011062`: `yandex_navi-7_10-universal-kia-mod-freshness.apk`.
- Yandex Core Bridge теперь передаёт отдельные monotonic timestamps для источников speed/limit/navigation и повторно поднимает подписку после фоновой паузы. Одинаковый envelope больше не делает застывшее значение фиктивно свежим; KIA применяет только source sample, который действительно обновлялся.
- Текущая скорость получила собственный freshness TTL: сначала используется свежий Yandex sample, затем свежий GPS fallback, а после expiry знак очищается. Значение `0` скрывает только текущую скорость и не выключает дорожное ограничение.
- Дорожный лимит остаётся независимым от маршрута и движения, обновляется в free-drive/фоне и повторяется после нового USB `connectionEpoch`. Устаревший либо явно обнулённый источник безопасно очищается вместо бесконечного удержания старого ограничения.
- Компас контролирует поступление реальных sensor samples, а не только регистрацию listener. При остановившемся rotation-vector он переходит на accelerometer + magnetic-field fallback, переинициализирует датчики и возвращает последний достоверный step без ожидания начала движения.
- Compass TX получил retry/keepalive только для реально недоставленного либо новой USB-сессии. Отложенный callback старого поколения больше не может подтвердить кадр новой сессии или вернуть дефолтное направление после долгой остановки.
- USB transport защищён от одновременных reader loops, callback старого поколения, зависшего read, reconnect storm и нарушения порядка write callbacks. Входной буфер изолирован по сессиям, backoff ограничен, а health-monitor отличает новую сессию от действительно остановившегося обмена.
- На Android 16 foreground service удерживает service wake-lock только после принятого ОС запуска; запрещённый запуск не оставляет скрытого фонового состояния.
- OTA-проверка вынесена в foreground service: после успешного ответа интервал составляет `1 ч`, а после сетевой ошибки повтор возможен на следующем `15-мин` background poll. KIA и Yandex имеют независимые timestamps, поэтому успех одного больше не откладывает retry второго.
- Добавлено настоящее системное уведомление `Обновления KIA`: оно объединяет доступные KIA/Yandex версии, не перезаписывается частичным результатом параллельной проверки, повторно появляется после перезагрузки и открывает раздел обновлений даже после восстановления процесса Activity.
- Android 13+ один раз запрашивает право на update notification. Автоматический диалог разрешён только при подтверждённой свежей стоянке; при движении, неизвестной или устаревшей скорости остаётся безопасное немодальное уведомление.
- KIA updater сравнивает валидный `updates/latest.json` с GitHub `releases/latest` и выбирает более новый источник, поэтому задержка обновления raw-манифеста больше не скрывает релиз. Для KIA, single/multipart Yandex обязательны имя, URL, SHA-256 и размер; same-version repack входит в notification fingerprint.
- Одновременные проверки Activity/Service и состояния KIA/Yandex теперь синхронизированы process-wide и обновляют общий `UpdateState` атомарно. Отложенная установка Yandex переживает гонку между service-check и Activity, не удерживая Activity сильной ссылкой.
- Медиа-профиль `TEYES / CC4`, его capture/TX и настройки музыки не изменялись.
- Проверено: `337` unit-тестов, `0 failures/errors/skips`; `lintDebug` и `lintRelease` — по `0 errors` / `72 warnings`; clean release build, ZIP, zipalign и APK Signature Scheme v2. На физическом Android 16 подтверждены sensor-stall recovery, 90 секунд Doze, Yandex background более 100 секунд, expiry speed state, UI и безопасный отказ FGS. Физический USB CAN-адаптер в этот прогон не подключался.

- Компас больше не ждёт начала движения после запуска магнитолы: после трёхсекундной защиты навигационного старта он однократно возвращает последний реально доставленный compass step. Неподтверждённый маршрут, восстановленный с диска после перезапуска, больше не блокирует компас и снимается, если живой источник его не подтвердил.

- `CMD_SPEED_LIMIT` стал независимым latest-only состоянием очереди TX: `NAV_OFF` больше не удаляет его, а reconnect воспроизводит сначала состояние маршрута, затем последний лимит. KIA также следит за USB `connectionEpoch` и принудительно переотправляет ещё свежий лимит, даже если его значение не менялось.
- KIA теперь принимает speed-поля из свежего snapshot `background_suspended` до удержания активного маршрута. Первый free-drive `state=off` больше не стирает только что полученный лимит.
- Yandex mod получил main-thread heartbeat раз в `1 с`: существующий Core Bridge повторно читает реальный Guide/Guidance snapshot и отправляет его KIA в foreground, background и free-drive без выдумывания данных. При остановке процесса Яндекса heartbeat прекращается, после чего KIA безопасно очищает устаревший лимит по TTL.
- Одинаковые heartbeat snapshot больше не перезапускают живой `AppService`, не удерживают второй receiver wake-lock и не перезаписывают `StateStore`/UI. Они дёшево освежают freshness/watchdog; любое изменение speed/limit/exceeded проходит сразу.
