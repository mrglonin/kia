# Люк: анимация и предупреждение перед сном TEYES

Релиз `23.18-sunroof` / `372` основан на `23.16` / `370` (`e5af812a`). Доступен через GitHub Release `v23.18-372` и манифест обновлений приложения. Отдельная диагностика компаса 371 в релиз не входит.

## Использование

Открыть **Настройки → Общее → Люк** и включить режим. Разрешить показ поверх других приложений. По умолчанию режим выключен, предупреждение после выключения зажигания и его звук включены, звук обычного открытия/закрытия выключен. Четыре переключателя сохраняются и входят в экспорт настроек (схема 52).

Кнопки «Открытие», «Закрытие» и «Предупреждение» показывают демонстрацию без изменения данных CAN. Предпросмотр доступен и при выключенном режиме. Отключение включённого режима сразу убирает текущее окно и звук.

## Поведение

- Первый достоверный кадр люка после подключения задаёт исходное положение без анимации.
- Изменение `закрыт → открыт` или `открыт → закрыт` показывает соответствующее движение стекла. Повторы не перезапускают окно. Движение занимает 900 мс, окно исчезает через 3,4 с.
- Известный открытый люк при подтверждённом ACC OFF вызывает предупреждение: та же миниатюра с мягкой красной пульсацией, без текста и карточки. Предупреждение сохраняется до подтверждения, закрытия люка, ACC ON или сна магнитолы.
- Касание любой точки предупреждения, обычная клавиша Android или поступившая клавиша MCU подтверждают его. Home/Recents, выключение экрана и штатный callback сна убирают окно и звук. Android/MCU могут не передавать приложению некоторые физические кнопки.
- Подтверждённое предупреждение не возвращается от одинаковых кадров или переподключения USB. Новое открытие люка или следующий цикл ACC ON→OFF допускают новый эпизод.
- Уже показанное предупреждение переживает потерю USB. Если фактическое ACC ON→OFF поступает в пределах 3 с после потери USB, допускается предупреждение по непосредственно предшествовавшему известному открытому люку. Одна потеря USB не считается выключением зажигания.
- Сигнал предупреждения: существующий ресурс `tpms6_error.wav` из проекта, совпадающий со штатным сигналом TEYES TPMS. Максимум три старта в 0/3/6 с; звук прекращается при подтверждении, закрытии, отключении, потере разрешения или остановке службы. Громкость и AudioFocus не меняются. Для обычного перехода доступен один сигнал.
- При активном предупреждении TPMS/RCTA окно люка уступает ему приоритет.
- На Android 12+ обычное окно использует допустимую прозрачность для передачи касаний другим приложениям; предупреждение принимает касание для подтверждения. Учтены [правила FLAG_NOT_TOUCHABLE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_TOUCHABLE).

## Источники и границы

Положение люка приходит существующим коротким кадром адаптера `0x76`. Для него отдельно хранятся монотонное время получения и поколение USB. Температурные кадры не обновляют свежесть люка; переподключение задаёт новый исходный отсчёт. Прошивка адаптера не меняется.

ACC читается через необязательный штатный `com.spd.system.service.SpdManager`: актуальный агрегат `DeviceStatusInfo.accStatus` и ранний `sendCommonToSouce(5, willPowerOff, 0)`, где `willPowerOff=1` означает ACC OFF. Сохранённая прошивка TEYES отправляет этот callback до таймера сна. Команда 8 используется только для завершения показа перед сном. Экран, USB и `getPowerState()` не используются как источник ACC OFF. Отсутствующий API даёт неизвестный ACC и диагностический статус; предупреждение по догадке не создаётся.

Нативный DTO не содержит времени последнего измерения; callback команды 5 служит свидетельством перехода. Опрос и callback упорядочиваются до чтения, поэтому запоздавший ответ опроса не отменяет более новое событие ACC.

Окно не удерживает экран включённым, не добавляет WakeLock и не меняет установленную задержку сна 30 с. Действующие механизмы фоновой службы сохранены. Доступ к vendor API, момент отключения усилителя, физический звук и маршрутизацию кнопок нужно проверить на конкретной магнитоле. Эмулятор и стенды не подтверждают эти свойства автомобиля.

Статус режима и источника ACC включён в **Общее → Краткий отчёт / Сохранить проблему**.

## Проверка

Общие задачи: `:app:testDebugUnitTest :app:lintRelease :app:assembleRelease`.

Дополнительно: `tools/tpms_regression.py`, `tools/compass_regression.py`, `tools/sunroof_teyes_regression.py`. Последний проверяет реальный класс наблюдателя с заменой границы Android/vendor Binder, включая неверные данные, переподключение и запоздавшие результаты.

Интерактивные проверки выполняются на отдельном Android-эмуляторе; команды `sunroof_qa_*` защищены существующим разрешением `android.permission.DUMP`, используют отдельную модель и не подменяют состояние автомобиля. Итоговая проверка и хеш APK опубликованы в [verification_372.json](../updates/verification_372.json) и приложены к GitHub Release.
